O Swagger, atualmente designado por OpenAPI Specification, é uma ferramenta de documentação, desenho e validação de APIs REST que permite descrever de forma estruturada os contratos de comunicação entre sistemas — endpoints disponíveis, métodos HTTP suportados, estrutura dos pedidos e respostas, e códigos de estado esperados. No contexto deste projeto, o Swagger foi utilizado como instrumento de especificação antecipada da API do Servidor Central, permitindo definir e validar o contrato de comunicação antes de qualquer linha de código ser escrita. Na fase de implementação, a integração do plugin `javalin-openapi` permitirá gerar automaticamente a especificação OpenAPI a partir das anotações dos handlers e disponibilizar a interface Swagger UI em `/swagger-ui`, eliminando a necessidade de ferramentas externas para validar o comportamento dos endpoints durante o desenvolvimento. O valor do Swagger neste projeto concentra-se assim em dois momentos distintos: antes da implementação, como ferramenta de alinhamento contratual entre o Software de Loja — enquanto cliente da API — e o Servidor Central — enquanto fornecedor —; e durante o desenvolvimento, como cliente HTTP visual integrado na própria documentação.

O endpoint de sincronização é o ponto de entrada do mecanismo de Delta Sync e o mais crítico da API, responsável pela receção dos pacotes de fecho de dia enviados por cada loja. Corresponde ao fluxo descrito no DS3 e DS4 e materializa os requisitos RF15 e RF16. A idempotência é garantida através de uma chave composta por `idLoja` e `idOriginalLoja` — um reenvio do mesmo pacote não produz duplicação de registos na base de dados central. A resposta inclui o campo `estadoConsolidacao`, que complementa a consulta disponível em `/consolidacao/{dataFecho}` e informa a loja sobre o estado global da rede para aquela data. Importa notar que o Servidor Central opera sempre sobre dados do dia anterior: os dados do dia em curso só ficam disponíveis após o fecho de dia da respetiva loja, limitação que deve ser comunicada visualmente nos dashboards da CEO conforme o ADR-01.
